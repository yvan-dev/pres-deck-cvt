# US-004 - Define live-demo guardrails and fallback rules

## Story

As a security reviewer, I want the live-demo segment bounded by explicit guardrails and fallback rules, so that the deck remains credible and safe even if live conditions change.

## Acceptance Criteria

1. Given a planned live Claude Code segment, when guardrails are defined, then approved demo data, forbidden sensitive content, and operator constraints are documented.
2. Given screenshots or supporting proof artifacts may be shown, when sanitization rules are written, then the projected material is safe for a mixed AOT audience.
3. Given the demo may fail or be shortened, when fallback rules are finalized, then the transition and recap still preserve the intended learning outcome.

## Notes

- This story protects the presentation from security and credibility failures during the live segment.
